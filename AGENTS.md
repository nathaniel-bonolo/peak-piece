# Peak Piece Agent Guide

Before evaluating, summarizing, modifying, or answering project-specific questions about Peak Piece, establish the current repository state rather than relying on old handoffs or assumptions.

Start with:

1. `project.json`
2. `README.md`
3. `production/FOUNDATIONS.md`
4. `production/DECISION-STATUS.md`
5. `production/WRITING-PHILOSOPHY.md`
6. `production/REVIEW-PROTOCOL.md`
7. the relevant character, story, lore, system, audit, or proposal files

Treat repository status explicitly. Do not collapse these into one category:

- One Piece canon
- Peak Piece foundational / locked material
- current draft implementation
- contested extensions
- active proposals
- rejected / superseded material
- your own inference

Peak Piece is a **reimagining**, not a fidelity-first repair project. Canon material may be deliberately replaced even when the project understands and respects what canon was doing.

For radical changes, inspect the relevant canon audit when one exists. If no audit exists yet, say so.

Do not stop at the first file when the question depends on connected character, faction, system, or story material.

Evaluate a direction according to its stated function, consequences, gains, losses, and execution rather than assuming similarity to canon is itself the goal.

If files conflict, surface the conflict and use explicit current status / authoritative files rather than silently blending versions.

If a user makes a factual claim about Peak Piece, verify it against the current repository when possible.
